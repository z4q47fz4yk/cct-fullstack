## 总纲

一个工程由若干工序组成，如何确定这些工序的施工策略，使得总体在成本、碳排放、工期之间取得平衡呢？

答案是：NSGAII 算法。本软件中，进行了四种不同施工模式的假定。在计算时，一组假定构成了一种施工策略组合，称为一个可能的解。使用 NSGAII 算法进行帕累托解集的求解，在该过程中，去除掉超出总工期、违反资源约束的解。每给定一个组合，都能求出成本、碳排放、工期。

## 施工模式定义

### 标准施工

数据库中现有数据，即标准施工产生的数据。

### 加速施工

通过延长每日工作时长、增加机械设备数量来加速。总工作量保持不变，故机械等造成的碳排放不变。因为工期减少，工人生活消耗减少，从而降低碳排放[^explain1.5]。

[^explain1.5]: 这个公式中的 1.5 为一个经验值。

$$\displaystyle C_G = \left(1- 1.5\times \frac{T_G - T_N}{T_N}\right) C_N$$

这里的 $C$ 表示 `Cost` 成本，$T$ 表示 `Time` 时间，下标 $G$ 表示加速模式，$N$ 表示 `Normal` 标准模式。

$$\displaystyle E_G = \frac{T_G}{T_N} \times E_N$$

这里的 $E$ 特指人员生活碳排放 [^1]。

[^1]: “人员生活”在数据库的 Resource 表中，但是不会从施工日报输入，假设所有人都生活在工地，则这部分碳排放可以使用总工日数 $\times$ 人员生活碳排放因子计算。

### 低碳施工

通过升级机械来完成低碳目标。这会导致机械成本增加 20%，机械与人员碳排放减少 40%，建筑垃圾[^2]减少 15%。

[^2]: 数据库中暂时还没有建筑垃圾这个类别，先不予考虑

## 考虑施工顺序

使用 CPM 法完成关键路径的计算。在 CPM 法过程中会产出若干中间变量：最早开始时间、最早完成时间、最晚开始时间、最晚完成时间。

CPM 的结果也决定了工程整体的工期。

## 考虑时间成本

$IRR = 5\%$

第一份施工日报的时间为**施工开始时间**，也就是时间成本的折现时间，记为第 0 天。

所有成本按月结算，成本发生时间为第 30 天的倍数，而不是真实的月底时间。

不考虑工程进度款，仅计算施工的成本。

**关键的简化假设**：每个工序对某项资源的使用在工序时间内是均匀的，而不考虑实际上的成本分布（忽略各项资源使用量随时间变化，或时间尺度上各资源占比变化）。

则该工序的成本现值使用 Python 表达如下：

```python=
def calculate_present_value(
    t_s: int,  # 施工开始时间（天）
    t_e: int,  # 施工结束时间（天）
    C: float,  # 工序总成本
    r: float,  # 月度折现率
) -> float:
    """
    计算施工成本的现值
    """
    D = t_e - t_s  # 工期总天数

    # 第一个结算时间点：t_s 之后的第一个 30 天倍数
    first_settlement = math.ceil(t_s / 30) * 30

    pv = 0.0
    k = 1

    for t_k in range(first_settlement, t_e + 1, 30):
        # 第 k 期覆盖的天数
        period_start = max(t_s, t_k - 30)
        period_end = min(t_e, t_k)
        delta_t = period_end - period_start

        # 成本比例 × 折现系数
        cost_ratio = delta_t / D
        discount_factor = 1 / ((1 + r) ** k)

        pv += C * cost_ratio * discount_factor
        k += 1

    return pv
```

举例：一个工序在第 15 天开始，第 95 天结束，则第一个月成本为 $(30-15)/T*C / (r+1)$, 第 $i$ 个月（$i=2,3$）成本为 $30/T*C / (r+1)^i$，第四个月成本为 $(95-30)/T*C / (r+1)^4$。

## 考虑资源约束

前提：“标准施工”未违反资源约束（这里可以确保至少存在一个解）。

目标：给定一个施工模式序列，去除掉不满足资源约束的解。

这里考虑资源约束，将使用量在时间轴平摊显得不太合适；而将原始的(资源-时间)曲线在时间轴上进行压缩比较麻烦。采用下述方案：不考虑施工时间的变化，将各个工序上每天的资源使用量变为原来的 $T/T_G$ 倍，只要时间轴上没有哪一天的资源使用量超标，就视为满足资源约束。
