# 核心概念

在开始使用软件之前，先了解以下核心概念。它们贯穿所有功能模块。

## 项目（Project）

项目是**数据隔离的顶层容器**。软件支持同时管理多个工程项目，每个项目拥有自己独立的工序、资源、日报、优化记录。切换项目后，所有页面都只显示当前项目的数据。

项目包含基本信息（名称、描述、状态）、规模信息（占地面积、建筑面积）、地点信息（省 / 市 / 地址）以及建筑概况（结构类型、抗震等级等）。

## 工序（Task）

工序是施工任务的最小组织单元，例如"基坑开挖""主体结构施工"。每个工序包含：

- **任务编码**：系统自动生成的唯一代号（`AUTO-N`）；
- **任务名称**：如"基础施工"；
- **工期**：预计施工天数（≥ 0.5 天）；
- **完成度**：0~1 之间的小数，表示当前进度；
- **前置任务**：该工序开始前必须完成的其他工序。

工序之间通过**依赖关系**连接，依赖类型包括：

| 类型            | 含义                  | 说明                      |
| --------------- | --------------------- | ------------------------- |
| FS（完成-开始） | 前置完成 → 本任务开始 | 最常见：A 做完 B 才能开始 |
| SS（开始-开始） | 前置开始 → 本任务开始 | A 开始后 B 即可开始       |
| FF（完成-完成） | 前置完成 → 本任务完成 | B 须等 A 完成后才能完成   |

依赖关系决定**关键路径**和**总工期**。

## 资源（Resource）

资源是施工中消耗的对象，分为五类：

| 类别 | 编码        | 示例                   |
| ---- | ----------- | ---------------------- |
| 人工 | `labor`     | 泥工、钢筋工、木工     |
| 机械 | `machinery` | 挖掘机、塔吊、人货梯   |
| 材料 | `material`  | 商品混凝土、钢筋、模板 |
| 运输 | `transport` | 重型卡车、渣土车       |
| 其他 | `others`    | 人员生活、临建设施     |

每个资源包含：

- **名称**（项目内唯一）
- **单位**（如 工日 / 台班 / m³ / 车次）
- **单价**（元 / 单位）→ 用于计算成本
- **碳排放因子**（kg / 单位）→ 用于计算碳排放
- **描述**

> 另有一个「公共资源」字典（全局只读），内含预置资源，可以一键批量拷贝到当前项目，避免重复录入。

## 资源使用（TaskResourceUsage）

记录"**某个工序在某个日期消耗了某种资源多少数量**"，是最核心的业务数据：

```
(工序, 日期, 资源, 使用量, 使用类型)
```

- **使用类型**：`ACTUAL`（实际发生，来自日报或实际记录）或 `PLANNED`（计划用量）；
- 同一工序同一天同一资源同一类型只能有一条记录（重复录入会提示冲突）。

资源使用数据是成本、碳排放计算的**唯一数据源**。

## 施工日报（Daily Report）

施工现场每天产出的 Excel 报表，记录了当天各资源的使用情况。软件支持：

1. **上传解析**：自动识别日报中的人员、机械、运输等数据块；
2. **核对修正**：将解析出的资源名称与项目资源字典匹配（精确匹配 / 新建 / 跳过），可手动调整；
3. **分配工序**：把每项资源用量分配到具体工序；
4. **确认提交**：一次性写入数据库。

详见[日报处理](/usage/daily-report)。

## 施工模式（Construction Mode）

每个工序在优化时可以从四种模式中选择一种：

| 模式         | 编码 | 工期              | 成本               | 碳排放              |
| ------------ | ---- | ----------------- | ------------------ | ------------------- |
| 标准施工     | 0    | 不变              | 不变               | 不变                |
| 加速施工     | 1    | 缩短（×加速比例） | 机械、人工成本上升 | 人员生活碳排减少    |
| 低碳施工     | 2    | 不变              | 机械成本 +20%      | 机械、人工碳排 -40% |
| 加速低碳施工 | 3    | 缩短              | 组合               | 组合                |

详细公式见[四种施工模式](../algorithm/modes)。

## 优化运行与帕累托解集

**优化运行（Optimization Run）**：一次完整的 NSGA-II 优化过程，包含配置参数、运行状态（等待 / 运行中 / 成功 / 失败）与结果。运行期间可随时**中断**。

**帕累托解（Pareto Solution）**：一个完整的施工方案，包含：

- 每个工序选择的**施工模式**（0~3）；
- 每个工序的**开始时间**（由依赖关系与开始偏移决定）；
- 该方案的总**成本**（现值）、**工期**、**碳排放**；
- 资源约束的**违反情况**（如有）；
- 峰值施工人数、临时用房间数（若配置了临时用房资源）。

**帕累托前沿**：所有互不支配的帕累托解的集合。"解 A 支配解 B"指 A 的三个目标都不差于 B 且至少一个更好。帕累托前沿上的方案没有绝对的优劣——**选择哪一个取决于决策者对成本、工期、碳排的偏好**。

## 资源约束与材料周转

- **资源约束（Resource Constraint）**：为某资源设置**日用量上限**。优化时，任何一天用量超过上限的方案会被剔除（实际是作为约束条件处理）。前提是"标准施工"方案不违反约束，以保证至少存在可行解。
- **材料周转配置（Resource Reuse Config）**：可周转材料（如模板、脚手架）按 `最大周转次数 × 实际周转次数` 折减碳排放因子，使碳排放计算更符合实际。

## 标签与图表（Tag & Chart）

用于**碳排放的维度化拆解**：

- **标签维度（Tag Dimension）**：一套独立的分类体系，如"碳排放来源""运输货物""地理位置"；
- **标签（Tag）**：维度下的树形节点，如"碳排放来源 → 施工机械 → 挖掘机"。资源、工序、用量三种实体都可以打标签；
- **图表（Chart）**：绑定若干标签作为**切片**，聚合每个标签子树下的碳排放量，生成饼图。例如"施工用材占比图""施工现场各部分占比图"。

详见[碳排放分析](/usage/emission)。

## 常用术语速查

| 术语       | 含义                                           |
| ---------- | ---------------------------------------------- |
| NSGA-II    | 非支配排序遗传算法第二代，经典多目标优化算法   |
| 帕累托最优 | 无法在不牺牲其他目标的前提下改进任一目标的状态 |
| CPM        | 关键路径法，用于计算总工期与关键工序           |
| IRR        | 内部收益率，软件中作为年折现率（默认 5%）      |
| 现值       | 未来成本按折现率折算到当前的价值               |
| 碳排放因子 | 单位资源用量对应的碳排放量（kg/单位）          |
