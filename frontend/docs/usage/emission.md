# 碳排放分析

碳排放分析用于**从多个维度拆解项目碳排放构成**。核心机制是"标签 → 图表"两级配置：

```
标签维度（分类体系）
  └── 标签树（维度内的层级标签）
        └── 打标（资源 / 工序 / 用量 三粒度）
              └── 图表定义（绑定标签作为切片）
                    └── 饼图 / 柱状图展示
```

## 第一步：配置标签维度

入口：**设置 → 碳排放标签**。

**标签维度**是一套独立的分类体系，例如：

| 维度       | 用途                                         |
| ---------- | -------------------------------------------- |
| 碳排放来源 | 建材、施工机械、施工用材与水电消耗、施工运输 |
| 运输货物   | 材料运输、生活垃圾、建筑垃圾、渣土           |
| 地理位置   | 生活区、施工区（预留）                       |

同一项目可建多个维度，每个维度下是一棵独立的**标签树**（名称在维度内唯一，父标签必须同维度）。

例如「碳排放来源」维度树：

```
碳排放来源
├── 建材（最终建筑物材料）
├── 施工机械
├── 施工用材与水电消耗
│   ├── 施工用材 → [地下工程支护, 主体工程支护, 辅材, 临建设施]
│   └── 水电消耗 → [外购电力, 外购自来水, 柴油, 光伏发电]
└── 施工运输
```

## 第二步：打标

三个打标粒度，应对不同拆分需求：

| 粒度                     | 说明                 | 适用场景                                         |
| ------------------------ | -------------------- | ------------------------------------------------ |
| **资源**（resource_tag） | 给资源打标签         | 按资源类型拆分，如"施工机械"                     |
| **工序**（task_tag）     | 给工序打标签         | 按施工部位拆分，如"地下工程支护"                 |
| **用量**（usage_tag）    | 给某条用量记录打标签 | 运输货物分类（同一车辆运多种货时必须用用量粒度） |

同一实体可跨维度打多个标签。打标入口：

- 资源：设置 → 资源管理 → 标签；
- 工序：任务管理 → 标签；
- 用量：资源使用录入 → 历史 → 标签（日报运输类导入时会自动打"运输货物"标签）。

## 第三步：配置图表

入口：**设置 → 碳排放图表**。

创建图表定义：

| 字段                                   | 说明                                                                                     |
| -------------------------------------- | ---------------------------------------------------------------------------------------- |
| 图表名称                               | 如"施工用材占比"                                                                         |
| 图表类型                               | 饼图等                                                                                   |
| **切片归属实体**（sliceEntity）        | `RESOURCE`（按资源标签）/ `TASK`（按工序标签）/ `USAGE`（按用量标签）/ `ANY`（任一命中） |
| **资源分类过滤**（resourceCategories） | 可选，如仅统计 `material` / `transport` / `energy` 类别资源                              |
| 绑定标签                               | 整组替换式设置，顺序即切片显示顺序                                                       |

### 切片聚合逻辑

每个绑定的标签 = 一个**切片**，其数值 = 该标签自身及**全部子孙标签**下实体的碳排放总和。

例如图表绑定"施工机械"标签（RESOURCE 模式），则所有打了"施工机械"或其子标签（挖掘机、塔吊…）的资源的碳排放都聚合到该切片。

> 碳排放口径与月度报表一致：SQL 聚合用量 SUM(quantity) 后，Python 层应用**资源周转折减**再乘碳排放因子计算排放。

### 打标互斥校验

为避免饼图**虚增**（同一碳排放被两个切片重复计入），系统做互斥校验：

- 任何实体的标签不得同时命中同一图表的**两个切片**（含父+子标签同时被绑定的场景）；
- `ANY` 图表还会检查关联实体的标签（如某用量的资源标签 + 用量标签）；
- 冲突时保存返回 **409**，需调整标签或图表切片配置。

## 第四步：查看图表

- **设置 → 碳排放总览**：项目整体碳排放概览（总排放、月度数、资源数、按类别排放）；
- **分析洞察 → 碳排放分析**：展示各图表的饼图 / 柱状图，支持 `usageType`、日期范围过滤。

## 常见问题

| 问题                    | 处理                                                                        |
| ----------------------- | --------------------------------------------------------------------------- |
| 饼图数据为空            | 检查标签是否已打、图表切片归属实体（RESOURCE/TASK/USAGE）是否与打标粒度一致 |
| 保存标签报 409 互斥冲突 | 标签命中了同一图表的多个切片，调整图表绑定或标签粒度                        |
| 运输类数据拆分不准      | 运输应按 **USAGE** 粒度打标（同一车辆运多种货物时按资源打标无法拆分）       |
| 图表按资源分类过滤无效  | 确认 `resourceCategories` 取值与资源类别（material/transport/energy…）一致  |

## 数据结构参考

```json
// 图表定义（ChartDefinition）
{
  "id": 1,
  "name": "施工用材占比",
  "chartType": "PIE",
  "sliceEntity": "RESOURCE",
  "resourceCategories": ["material"],
  "tags": [{ "id": 11, "name": "施工用材" }]
}

// 饼图数据（PieSlice）
{
  "tagId": 11,
  "tagName": "施工用材",
  "emissionKg": 45230.5
}
```
