# 任务管理（工序）

任务管理页面（左侧导航「任务管理」，图标 view_timeline）用于维护项目中的工序、工序间的依赖关系，并以甘特图形式展示进度。

## 页面功能

- **甘特图**：按时间轴展示各工序的工期与先后关系，红色标注**关键路径**工序；
- **任务列表**：表格形式展示任务（编码、名称、工期、完成度、前置任务、是否关键路径）；
- **添加任务**：右下角悬浮按钮（TaskFAB）新建工序；
- **进度统计**：总任务数、总工期（各工序工期之和）、关键路径工期。

## 创建任务

点击添加按钮，填写：

| 字段     | 说明                               |
| -------- | ---------------------------------- |
| 任务编码 | **自动生成**（`AUTO-N`），无需填写 |
| 任务名称 | 必填，如"基坑开挖"                 |
| 工期     | 预计天数，≥ 0.5                    |
| 完成度   | 0 ~ 1（如 0.5 表示完成 50%）       |
| 任务描述 | 可选                               |
| 前置任务 | 可选，可同时指定多个前置任务       |

保存后任务出现在甘特图与列表中。

## 设置前置依赖

任务的**前置任务**决定了施工顺序：

1. 在任务卡片/表格中选择任务 → 管理前置任务；
2. 从「可选前置任务」中选择（系统会排除自身与会造成循环依赖的任务）；
3. 为每个前置任务设置**依赖类型**：FS / SS / FF（见[核心概念](../guide/concepts)）。

::: tip

- 同一任务可设置多个前置任务，任务的实际最早开始时间取所有前置约束的最大值；
- 删除任务时，若其他任务依赖它，系统会拒绝（返回 409 冲突），需先解除依赖。
  :::

::: info 需要滞后/提前关系怎么办？

依赖关系不再支持"滞后天数（lag）"。若需要某个工序在另一工序完成后隔几天再开始，
可以**添加一个过渡工序**模拟：

- 例如 A 完成后 3 天 B 才能开始 → 添加过渡工序 T（工期 3 天），建立 A → T → B 两条 FS 依赖；
- 过渡工序同样会出现在甘特图与关键路径计算中，选择"完成-开始（FS）"依赖即可。

这样所有排程口径（任务管理、计划估算、NSGA-II 优化）完全一致。
:::

## 关键路径与甘特图

系统使用**关键路径法（CPM）**自动计算：

- 每个工序的最早/最晚开始、完成时间与总浮动时间；
- 总浮动时间为 0 的工序为**关键工序**（甘特图中标红）；
- **关键路径工期 = 项目总工期**，是优化中"工期"目标的基准。

::: tip
想缩短项目总工期，只能压缩关键路径上的工序（加速施工模式），非关键工序压缩不影响总工期。
:::

## 进度统计

页面顶部展示：

| 指标         | 含义                             |
| ------------ | -------------------------------- |
| 总任务数     | 当前项目工序总数                 |
| 总工期       | 所有工序工期之和（不含并行）     |
| 关键路径工期 | 项目实际总工期（考虑并行与依赖） |

## 数据结构参考

```json
// 任务（Task）
{
  "id": 1,
  "code": "AUTO-1",
  "name": "基坑开挖",
  "description": null,
  "duration": 10.0,
  "completed": 0.0,
  "is_critical": true,
  "predecessors": [
    { "task_id": 2, "predecessor_id": 1, "type": "FS" }
  ]
}

// 进度统计（ScheduleStats）
{
  "total_tasks": 12,
  "total_duration": 96.0,
  "critical_duration": 55.0
}
```
