# NSGA-II 优化

NSGA-II（非支配排序遗传算法第二代）是本软件的核心算法，由 pymoo 库实现。本文面向使用者解释它的工作原理，帮助理解优化结果的含义与参数的作用。

## 问题建模

### 决策变量

一个完整施工方案 = 每个工序的（模式, 开始时间偏移）：

```
方案 = { 工序1: (模式, 偏移), 工序2: (模式, 偏移), ..., 工序N: (模式, 偏移) }
```

- **模式**：0~3（标准 / 加速 / 低碳 / 加速低碳），见[四种施工模式](./modes)；
- **偏移**：0 ~ 最大偏移天数（默认 60）的整数，表示该工序在不违反依赖关系的前提下，最早开始时间可额外延后的天数（用于平衡资源峰值）。

因此决策空间大小为 `4^N × (偏移+1)^N`——工序一多，穷举完全不可行，这正是需要遗传算法的原因。

### 三个目标（全部最小化）

| 目标      | 含义                                                                               |
| --------- | ---------------------------------------------------------------------------------- |
| f1 成本   | 全部工序成本的**现值**（按月度结算 + IRR 折现），见[成本现值计算](./present-value) |
| f2 碳排放 | 全部资源用量 × 碳排放因子（含周转折减、模式影响）之和                              |
| f3 工期   | 按依赖关系用**关键路径法**计算的总工期                                             |

### 约束

- **资源日用量约束**：任何一天、任一受约束资源的用量不得超过上限；
- 约束处理方式：把每个工序的总用量按工期平均摊到每一天，若某天峰值超限则该方案视为违反约束（超出量为违反量）。

> **资源约束判定口径**：把每个工序对该资源的总用量，除以该工序**调整后工期**（加速后为 `T_G`），均摊到其覆盖的每一天，得到"日用量曲线"，再取全项目每天的最大值与该资源上限比较。超过则视为违反约束（超出量为违反量）。
>
> 因此：
>
> - **加速施工（模式 1/3）会提高受约束资源的日量线**——同一总用量被压缩到更短工期，属预期行为，不代表"改了模式资源需求增加"；
> - **仅对已配置了 `resource_constraint` 的资源生效**：未配置的资源数量再多也不参与约束判定；
> - 该判定是"按工期均摊"的**近似**，并非逐日的真实用量曲线；符合计划阶段数据按月录入、无法逐日描述的现状。

## 帕累托支配

对两个方案 A、B，若 A 的三个目标都不比 B 差，且至少一个目标严格优于 B，则称 **A 支配 B**。

- 被支配的方案没有保留价值（存在全面更好的方案）；
- **非支配解集（帕累托前沿）**：所有不被任何其他方案支配的方案集合；
- 前沿上的方案互有优劣：省钱的工期长，低碳的成本高……**选择哪个取决于决策者的偏好**。

## NSGA-II 算法流程

```
1. 随机生成初始种群（pop_size 个随机方案）
2. 重复 max_gen 代：
   a. 评估所有个体（计算成本/碳排/工期/约束违反）
   b. 非支配排序：把种群分成若干层（第 1 层 = 当前前沿，第 2 层 = 去掉第 1 层后的前沿，…）
   c. 拥挤度计算：同一层内按目标空间密度排序（前沿稀疏处的个体优先保留）
   d. 选择（锦标赛）、交叉、变异 → 生成子代
   e. 父代+子代合并 → 精英保留策略选择下一代
3. 输出最终的非支配前沿（去重：目标值近似相等的解只保留一个）
```

关键特性：

- **精英保留**：最优个体不会丢失；
- **拥挤度距离**：让前沿在目标空间尽量均匀分布，避免解聚集在局部；
- **去重**：多个不同的模式/偏移组合可能映射到相同的目标值，结果会按 (成本, 碳排, 工期) 去重。

## 与施工业务结合的计算细节

每次评估一个方案时：

1. 按模式调整各工序工期（加速 × 比例）；
2. 按模式乘数修正各工序的成本与碳排放（分材料/机械/人工施工/人员生活/运输五列）；
3. 用拓扑排序 + 依赖关系计算各工序最早开始时间与总工期；
4. 计算成本现值（月度结算、IRR 折现）；
5. 计算资源约束违反量、峰值施工人数、临时用房间数（若配置）。

## 参数含义与调参建议

| 参数         | 默认 | 作用               | 建议                                     |
| ------------ | ---- | ------------------ | ---------------------------------------- |
| 种群大小     | 100  | 每代个体数         | 工序多时调大（200~300）；过小易早熟      |
| 最大代数     | 100  | 迭代轮数           | 观察进度曲线，前沿不再改善即可停止       |
| 名义年利率   | 0.05 | 成本折现率         | 按企业资金成本设置                       |
| 加速工期比例 | 0.8  | 加速模式工期缩放   | 按实际赶工能力设置（0.5~1.0）            |
| 最大偏移天数 | 60   | 开始时间可延后上限 | 需要均衡资源峰值时调大；希望尽快开工调小 |

::: tip 调参经验

- 结果中可行解很少 / 前沿不完整 → 增大种群与代数；
- 运行太慢 → 适当减小种群或代数（工序多时评估开销线性增长）；
- 约束过严导致无解 → 放宽资源限制或检查标准方案是否已超限。
  :::

## 运行状态与中断

- 优化是**后台异步任务**：创建后立即返回运行 ID，前端轮询状态（PENDING → RUNNING → SUCCESS / FAILURE）；
- 每完成一代，进度（curr_gen / max_gen）落库；
- 可随时**中断**（PATCH 接口置位中断标记，引擎每代检查后合作式终止），中断结果标记为失败并记录"优化已被用户中断"，不产生解。
