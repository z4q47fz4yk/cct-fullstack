# 关键路径法（CPM）

关键路径法（Critical Path Method）用于：在给定工序与依赖关系的条件下，计算**项目总工期**、各工序的时间窗口与**关键路径**。它是软件中"工期"目标的计算基础。

## 基本概念

对每个工序计算四个时间：

| 名称         | 缩写 | 含义                               |
| ------------ | ---- | ---------------------------------- |
| 最早开始时间 | ES   | 在所有前置约束下最早可以开始的时间 |
| 最早完成时间 | EF   | ES + 工期                          |
| 最晚开始时间 | LS   | 不拖延总工期的最晚开始时间         |
| 最晚完成时间 | LF   | LS + 工期                          |

**总浮动时间** = LS − ES。浮动为 0（或接近 0）的工序称为**关键工序**，它们组成**关键路径**。

## 计算步骤

### 1. 前向传递（求 ES / EF）

按拓扑顺序（依赖在前）遍历：

- 无前置任务：ES = 0；
- 有前置任务：按依赖类型计算候选开始时间，取最大值：

| 依赖类型        | 前置约束                  |
| --------------- | ------------------------- |
| FS（完成→开始） | ES ≥ 前置 EF              |
| SS（开始→开始） | ES ≥ 前置 ES              |
| FF（完成→完成） | ES ≥ 前置 EF − 本工序工期 |

**项目总工期 = 所有工序 EF 的最大值。**

### 2. 后向传递（求 LS / LF）

按拓扑逆序遍历：

- 无后继任务：LF = 项目总工期；
- 有后继任务：LF = min(各后继约束下的最晚完成时间)。

### 3. 识别关键路径

总浮动时间 |LS − ES| < 0.001 的工序为关键工序。**压缩关键工序的工期才能缩短总工期**。

## 循环依赖检测

若依赖关系存在环（如 A→B→A），拓扑排序无法遍历所有节点，系统判定无法计算关键路径并返回空结果（前端表现为甘特图/统计无关键路径数据）。创建前置任务时系统会提前检测并拒绝循环依赖。

## 在软件中的应用

| 场景         | 用途                                                                      |
| ------------ | ------------------------------------------------------------------------- |
| 任务管理     | 甘特图标红关键路径工序、进度统计（关键路径工期）                          |
| NSGA-II 优化 | 每个候选方案按当前模式的工期重新计算总工期（目标 f3）与各工序最早开始时间 |
| 方案回放     | 帕累托解甘特图按运行快照的依赖拓扑展示施工排程                            |

## 示例

工序：A（5 天）→ B（3 天）→ C（4 天），B 与 D（2 天）并行，D 无前置：

```
A: ES=0  EF=5  LS=0  LF=5  浮动=0  ✓关键
B: ES=5  EF=8  LS=5  LF=8  浮动=0  ✓关键
C: ES=8  EF=12 LS=8  LF=12 浮动=0  ✓关键
D: ES=0  EF=2  LS=10 LF=12 浮动=10 ✗非关键
```

总工期 = 12 天（关键路径 A→B→C）。D 推迟 10 天内开工都不影响总工期。
