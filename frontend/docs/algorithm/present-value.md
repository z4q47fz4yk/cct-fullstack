# 成本现值计算

施工成本发生在未来不同时间点，直接相加会忽略**资金的时间价值**（今天的钱比明天的钱更值钱）。软件将全部工序成本折算为**现值（Present Value）**作为优化目标之一。

## 计算规则

- **折现率**：年名义利率 IRR（默认 5%），按月折算：月折现率 `r = IRR / 12`；
- **起点**：第一份施工日报的日期 = 施工开始时间（第 0 天）；
- **结算方式**：成本**按月结算**，结算时间点为第 30 天的倍数（30、60、90…），而非自然月月底；
- 不考虑工程进度款，仅计算施工成本。

## 关键简化假设

> 每个工序对某项资源的使用在工序时间内是**均匀**的，忽略实际成本分布（不考虑资源用量随时间变化或各资源占比随时间变化）。

因此一个工序的总成本 C 可按时间比例分摊到各结算周期。

## 计算公式

对单个工序（开始 t_s，结束 t_e，总成本 C）：

```
D = t_e - t_s                      # 工期
第一个结算点 = ceil(t_s / 30) × 30 # t_s 之后第一个 30 的倍数

现值 PV = Σ [ (该周期覆盖天数 / D) × C × 1/(1+r)^k ]
```

其中 k 为周期序号（1, 2, 3…），每 30 天递增。

### 示例

工序第 15 天开始、第 95 天结束（D = 80），总成本 C：

| 周期               | 覆盖天数     | 成本比例 | 折现       |
| ------------------ | ------------ | -------- | ---------- |
| 第 1 个月（t=30）  | 30 − 15 = 15 | 15/80    | × 1/(1+r)  |
| 第 2 个月（t=60）  | 30           | 30/80    | × 1/(1+r)² |
| 第 3 个月（t=90）  | 30           | 30/80    | × 1/(1+r)³ |
| 第 4 个月（t=120） | 95 − 90 = 5  | 5/80     | × 1/(1+r)⁴ |

即：

```
PV = C × [ (15/80)/(1+r) + (30/80)/(1+r)² + (30/80)/(1+r)³ + (5/80)/(1+r)⁴ ]
```

## 为什么用现值做目标

两个方案总成本相同，但一个"前期投入大、后期回款快"，另一个"前期省、后期花得多"，它们的**现值不同**：

- 现值把时间维度纳入成本比较——**越早发生的成本权重越大**；
- 在施工模式优化中，加速模式虽然总成本上升，但工期缩短使成本更早发生、折现损失更小，现值差异能更真实地反映资金占用成本。

## 与优化结合

- 每个候选方案中，各工序按最早开始时间（CPM 计算）确定 t_s / t_e；
- 各工序成本按模式乘数修正后，分别计算现值再求和 = 方案成本目标 f1；
- 未开工的成本按折现率逐年"缩水"，因此**压缩工期本身也能降低成本现值**（资金提前回流），这是时间与成本目标之间的内在耦合。
