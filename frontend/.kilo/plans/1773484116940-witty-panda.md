# 集成状态管理到日报步骤导航组件的计划

## 目标

将 `report.ts` 中的状态管理逻辑集成到 `DailyReportStepsNav.vue` 中，实现基于状态的步骤导航控制，并支持持久化当前阶段以便中途退出后自动重定向。

## 当前状态分析

### DailyReportStepsNav.vue 的跳转逻辑

- 使用路由路径匹配确定当前步骤 (`currentStepIndex`)
- `canNavigateToStep` 基于当前步骤和数据存在性允许导航：
  - 可导航到当前或之前步骤
  - 如果有解析数据，可导航到 review
  - 如果有分配数据，可导航到 allocate/confirm
- `navigateToStep` 使用 Vue Router 跳转
- `getStepStatus` 基于索引返回 completed/current/pending

### report.ts 的状态管理

- 使用 Pinia 定义 `useDailyReportStoreV2`
- 管理解析资源、映射决策、分配状态
- 有计算属性如 `mappingDecision`, `resourceUsages`, `summaryStats`
- 缺少明确的步骤/阶段状态管理

## 实施计划

### 1. 在 report.ts 中添加持久化步骤状态管理

- 添加 `currentPhase = useStorage<'PENDING' | 'MAPPING' | 'ALLOCATING' | 'COMPLETED'>('current-phase', 'PENDING')`
- 添加 `currentStepIndex` 计算属性，基于 phase 映射到步骤索引 (PENDING=0, MAPPING=1, ALLOCATING=2, COMPLETED=3)
- 添加 `canNavigateToStep` 方法，基于 phase 和数据状态判断是否可导航
- 在 API 调用成功后直接赋值 `currentPhase.value`：
  - `confirmMapping` 后设为 'MAPPING'
  - `allocateResources` 后设为 'ALLOCATING'
  - `submitReport` 后设为 'COMPLETED'

### 2. 修改 DailyReportStepsNav.vue

- 导入 `useDailyReportStoreV2` 而非 `useDailyReportStore`
- 移除本地 `currentStepIndex` 计算，使用 store 的 `currentStepIndex`
- 更新 `canNavigateToStep` 调用 store 的方法
- 更新 `getStepStatus` 使用 store 的状态
- 更新 `stats` 使用 store 的统计数据（映射到 `summaryStats`）
- 移除本地步骤逻辑，依赖 store

### 3. 更新步骤完成逻辑

- API 调用成功后自动更新 `currentPhase`，无需额外函数
- 在页面组件中根据 `currentPhase` 重定向到对应步骤
- 确保状态正确推进和数据验证

- 确保状态同步和数据一致性
